# UI Craft — テンプレ感を脱し、らしさを宿す

## このスキルの狙い

動くUIを作るのは簡単になった。だから差がつくのは「動くか」ではなく「誰かが見て
**いいねと思うか**」。AIやスターターテンプレが出すUIには共通の"におい"がある —
どこかで見た配色、均一な余白、弱い階層、ホバーもしない静止画のようなコンポーネント。
このスキルのゴールは、その"におい"を消し、**意図（なぜこの見た目か説明できる）**と
**らしさ（このプロダクトならではの個性）**を宿すこと。

判断に迷ったら常にこの2問に戻る:

1. **意図**: この色・サイズ・余白を「なんとなく」ではなく理由付きで選べているか？
2. **らしさ**: これを別プロダクトにそのまま貼っても違和感がないなら、まだ無個性。

## 使い方（2モード）

### モードA: UIを生成する

実装に入る前に、頭の中で（または短く宣言して）**デザイン方針を先に決める**。
コードを書きながら色や余白を「その場のノリ」で選ぶのが、テンプレ感の最大の原因。
先に土台を固める:

1. **キャラクター1語** — このUIは何者か（例: 落ち着いた/機敏/武骨/やわらかい/高級）。
   以降の判断の憲法になる。
2. **カラー** — ブランドの主役色を1つ決める。ニュートラルは純グレーではなく主役色を
   ほんの少し混ぜた"色付きグレー"に。黒は `#000`、白は `#fff` を避ける。詳細は
   `references/color-and-type.md`。
3. **タイポ** — フォントとタイプスケールを決め、見出しと本文で明確な差をつける。
   同上ファイル参照。
4. **スペーシング** — 4px または 8px ベースのスケールを1本決めて全体で守る。余白は
   「均一」ではなく「意味に応じて強弱」。詳細は `references/layout-and-spacing.md`。
5. **実装** — 上記を守ってコードを書く。書いたら必ず下記チェックリストで自己レビュー。

方針は長文でなくてよい。「落ち着いた青系・Inter・8pxグリッド・情報密度は低め」程度の
一言宣言で十分。**重要なのは、書き始める前に決めてあること。**

### モードB: 既存UIをレビュー・改善する

コードやスクショを受け取ったら、いきなり直さず**まず診断**する。
`references/review-checklist.md` を読み、以下を順に見る:

1. **テンプレ臭の検出** — `references/anti-template-tells.md` の"におい"リストと
   照合。当てはまるものを具体的に指摘（`indigo-500 のまま`、`全カード同じ影`など）。
2. **意図の欠落** — 色/サイズ/余白の中で「理由が説明できない」ものを洗い出す。
3. **らしさの欠落** — 別プロダクトに貼っても成立してしまう度合いを評価。
4. **改善提案** — 優先度順に。**なぜ良くなるか**を必ず添える。破壊的な作り直しではなく、
   効果の大きい少数の変更から提案する（配色の再定義 > 余白の階層化 > 1つの署名的ディテール、の順が効きやすい）。

ユーザーの好みを勝手に上書きしない。既存の意図が読めない箇所は「ここは意図的？」と
確認する。

## 実装後の自己レビュー（生成・改善どちらでも必須）

出力する前に、最低でもこの観点を通す。1つでも引っかかったら直してから出す:

- **配色**: 主役色は決まっているか。ニュートラルは色付きか。純黒・純白を使っていないか。
  デフォルトの紫/藍（`#6366f1` 系）をそのまま使っていないか。
- **タイポ**: 見出しと本文にサイズ・ウェイト・行間の明確な差があるか。全部が同じ大きさで
  のっぺりしていないか。
- **階層**: 画面を見て「一番大事な要素」が一目でわかるか。全部が主張して競合していないか。
- **余白**: 余白が均一すぎないか。関連する要素は近く、無関係な要素は遠く（近接の原則）
  なっているか。
- **状態・ディテール**: hover / focus / active / disabled、空状態、ローディングを
  用意したか。トランジションはあるか。フォーカスリングを消していないか（アクセシビリティ）。
- **コンテンツ**: プレースホルダが "Card Title" や lorem ではなく、それらしい実データか。
- **らしさ**: 記憶に残る署名的ディテールが最低1つあるか。

詳細な判断基準が要るときだけ references を読む。毎回全部読む必要はない。

## 参照ファイル

- `references/anti-template-tells.md` — AI/テンプレUIの具体的な"におい"と、その置き換え方。
  レビュー時と、生成後の自己チェック時に参照。
- `references/color-and-type.md` — 配色とタイポの実践ルール（数値・具体例つき）。
- `references/layout-and-spacing.md` — レイアウト・余白・階層・コンポーネント質感。

## 大原則（迷ったらここ）

- **制約が個性を生む**: 色を増やすほど、角丸を混ぜるほど、フォントを足すほど安くなる。
  少ない要素を意図的に使う方が"らしさ"は出る。
- **なぜを言える状態を保つ**: すべての見た目の選択に一言の理由が言えること。それが
  「AIがなんとなく出した」との最大の違い。
- **実データで確かめる**: きれいなダミーではなく、長い日本語・空・エラー・極端な件数など
  現実の入力で崩れないUIが、実際に使われるUI。
