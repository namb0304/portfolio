- 目的: `/design-lab` の3案（A/B/C）を作る前の下調べ。

  ピクセル単位のスクリーンショット比較はこのセッションのツール制約でできていない。
  色・モーションの記述は、取得結果＋既知の情報を合わせたもの。**推定を含む**。

## 1. rauno.me

| 観点 | 観察 |
|---|---|
| 最初の3秒 | 氏名 → "Estonian interaction designer" → マニフェスト調の短文が積まれる。作品一覧が先に来ない |
| Typography | 装飾なし。ナビも `Craft` / `Projects` / `Field Notes` と素のラベル |
| 情報密度 | **意図的に低い**。1画面に置く情報を絞り、ページ全体を「余白でペースを作る」設計 |
| 作品の見せ方 | 時系列の一覧ではなく `Devouring Details` / `Craft` という**概念でのグルーピング** |
| personality | 作品数ではなく「何を大事にしているか」の宣言（Make it fast. Make it beautiful.）で出す |
| interaction | "Email Copied" のようなマイクロフィードバック。**インタラクション自体がポートフォリオの中身** |

**取るもの**: インタラクションを「飾り」ではなく「主張の証拠」として置く考え方 → Direction B の芯。
**取らないもの**: 密度の低さ。本人は見せる事実が多いので、そのまま真似ると薄く見える。

## 2. joshwcomeau.com

| 観点 | 観察 |
|---|---|
| 最初の3秒 | ナビ → "Articles and Tutorials"。**コンテンツが主役で、自分が主役ではない** |
| Typography | 記事タイトルにウェイト差。見出しは過剰に大きくしない |

**取るもの**: 「全部を最初に出さず、段階的に開く」導線設計 → TOPの長さを半分にする根拠。
**取らないもの**: 口語・絵文字のトーン。本人の実直さと合わない。

## 3. brittanychiang.com

| 観点 | 観察 |
|---|---|

## 4. linear.app

| 観点 | 観察 |
|---|---|
| Hero | "The product development system for teams and agents" を**極端に大きく**。製品画像はHeroの下 |
| Typography | 見出しと本文のスケール差が大きい。サブコピーは一段落とす |
| 製品UIの見せ方 | **装飾イラストではなく実物のUI**を全幅で、左右交互に配置。これが信頼性の担保になっている |
| リズム | 特集セクションは3カラムの反復でケイデンスを作る |
| 密度 | 中。余白で認知負荷を抑える |
| 色 | 背景はニュートラルに保ち、**色は製品スクリーンショットの中にだけ存在する** |

**取るもの**: 「背景は静かに、色は製品画面の中に」という配色の役割分担。実物UIを信頼性の証拠として置くこと。
**取らないもの**: 紫〜青のグラデーション。禁止事項そのもの。

## 5. vercel.com

| 観点 | 観察 |
|---|---|
| Hero | "Agentic Infrastructure" + サブ + CTA 2つ（Deploy now / Talk to sales） |
| 色 | **黒と白のコントラストを極端に**。アクセントはほぼ使わない |
| 製品の見せ方 | UIスクショではなく**数字による社会的証明**（"Zapier serves over 100 million monthly website visits"） |
| リズム | 見出し + 機能リスト + CTA のブロックを反復 |
| 密度 | 機能タグ（Durable Orchestration 等）で具体性を出しつつ、量は抑える |

**取るもの**: 抽象 → 具体へ降りていく順序。CTAを2つに固定すること。
**取らないもの**: 幾何モチーフ（三角形）とモノクロ極振り。本人には「実際に動いている現場」という温度があり、モノクロだと今回の反省点（質素すぎる）に戻る。

## 6. stripe.com

| 観点 | 観察 |
|---|---|
| Hero | 「事業成長を支える金融インフラ。」+ **波状のシグネチャーグラフィック** |
| 色 | フラットな色面ではなく**実写写真**（会場・オフィス）を背景に使い、有機的なグラデーションを作る |
| 製品UIの見せ方 | スクショを単独で置かず、**説明文の中に埋め込む**。文脈の中でUIを見せる |
| リズム | 密な情報ゾーンと視覚的な休符を交互に |
| 日本語 | 見出しの日本語が明確にデザインされている（英語サイトの翻訳に見えない） |

**取るもの**: (1) シグネチャーグラフィックを1つ持つこと。(2) **日本語の見出しをデザインの中心に据えること**。(3) UIを文中に埋める見せ方。
**取らないもの**: 虹色グラデーション。

## この7サイトから引いた結論（3案の前提）

1. **色は背景ではなく“中身”に持たせる** — Linear と Stripe の共通点。今回の3案はすべて「製品画面の中に色がある」状態を基本にする。
2. **最も模倣されている構図を避ける** — 左sticky2分割（Brittany 型）、黒白極振り（Vercel 型）、紫青グラデ（テンプレ型）は使わない。
3. **シグネチャーを1つ持つ** — Stripe の波に相当するものを、本人の経験からしか出てこないモチーフで作る。
   - A: 飲食店（インド・ネパール料理）に由来する**サフラン色**と、日本語の**明朝体見出し**
   - B: 「動く ≠ 使われる」を**切り替えられるインタラクション**そのものに落とす
   - C: 「実運用している」を**稼働状態の視覚言語**に落とす（ダッシュボードにはしない）
4. **日本語をデザインの主役として扱う** — Stripe Japan が唯一やっていたこと。英語ラベル + mono + uppercase に逃げない。
5. **段階的に開く** — Josh の `Show more` 的な考え方で、TOPは「興味を持たせて詳細ページへ送る」役割に限定する。
